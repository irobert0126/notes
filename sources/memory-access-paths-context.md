## What the diagram shows

The diagram draws one hardware structure: inside the SM are the warp scheduler, register file, ALU, LSU, L1, shared memory, constant cache, and TMA unit. Outside the SM are the GPU MMU, L2, memory controller, HBM, Copy Engine, host memory, and a peer GPU. On top of this structure are six access paths, one color each:

- **Blue ①: direct LD/ST.** Warp → LSU → L1 → L2 → HBM.
- **Teal ②: cp.async.** The LSU computes the global address and the data is written straight into shared memory without passing through registers. Indirect access is also in this category.
- **Gray ③: copy and fill.** Host → PCIe → Copy Engine → HBM, bypassing the SM.
- **Orange ④: pointer in parameters.** Read through the constant bank. It is a pointer value, not a data access.
- **Pink ⑤: CUDA graph.** The GPU front-end schedules the kernels as graph nodes.
- **Purple ⑥: TMA and NVLink.** TMA writes a whole tile into shared memory. NVLink cross-GPU writes are dashed because they are untested.

Hook points H1–H6 are marked on the diagram:

- **H1 allocator:** PyTorch allocator alloc/free, which gives the block lifetime. This runs on the CPU side.
- **H2 CUPTI launch:** reads pointers from kernel parameters. The args mode hooks here.
- **H3 CUPTI API:** pointers for memcpy and memset. cuMemsetD8 is missed here.
- **H4 Sanitizer instrumentation:** attached to the LSU. It instruments every LD/ST, atomic, and cp.async. It is the only point that gives the read/write type and the virtual address. The exact mode hooks here.
- **H5 TMA:** CUPTI only sees the CUtensorMap base address.
- **H6 CUDA graph:** there is no usable hook during capture. Sanitizer crashes under capture.
- **MMU / L2 / HBM:** no per-access hook.

The status strip at the bottom gives the result of each category in both modes:

| Category | exact (Sanitizer) | args (CUPTI) |
|---|---|---|
| ① Direct LD/ST | Reads and writes correct | Cannot tell read from write |
| ② Indirect / cp.async | Both captured | Indirect missed; cp.async has no R/W |
| ③ Copy / fill | memcpy correct | cuMemsetD8 missed |
| ④ Pointer in parameters | No access, not counted | False positive |
| ⑤ CUDA graph | Crashes during capture | Missed |
| ⑥ TMA / NVLink | Untested (A100 only) | TMA shows base address only; NVLink invisible |

## Results

On A100, exact mode (Compute Sanitizer) is correct on all 15 runnable scenarios. The only gap is CUDA graph, which cannot run because Sanitizer crashes during capture. args mode (CUPTI) is correct on 11 of 16 scenarios. Its problems fall into three groups: it cannot tell reads from writes, it misses indirect access and cuMemsetD8, and it reports pointers passed as parameters as accesses even when the kernel never touches them. TMA and NVLink have not been validated on A100. They need H100/B200 hardware or a multi-GPU setup.

The real workload was only run with torchrec `--world_size 1`. ddp-adam ran in both modes. exact peaked at 28.46 GiB, and a 1,360 MiB tensor in that run had no reads or writes in either iteration. fsdp-adam has not been run in exact mode. ddp-shampoo was only run in args mode. fsdp-shampoo could be captured in exact mode, but its 40 GB trace is too large to analyze. exact is expensive: about 78 seconds per iteration, roughly 100x slower, with about 6 GB of extra GPU memory per card, and launches are serialized.

## Open questions and limitations
- All measurements are single-GPU A100. The 2-GPU H100 session title is misleading: that session did not run a 2-GPU experiment. It declined a request from another session.
- The order of L1 and MMU is not drawn precisely, and it is not confirmed whether LDC goes through the LSU.
- The hook positions were inferred from what each API does. The hook implementations were not checked line by line.
- Hardware paths and component positions are schematic, not from an exact hardware reference.
- Address values such as 0x00007f3a40001414 are illustrative, not from a real trace.

def _pts(d):
    pts, x, y = [], 0.0, 0.0
    for cmd, args in re.findall(r"([MHVL])([^MHVL]*)", d):
        n = [float(v) for v in re.findall(r"-?\d+(?:\.\d+)?", args)]
        if cmd in "ML":
            x, y = n[0], n[1]
        elif cmd == "H":
            x = n[0]
        else:
            y = n[0]
        pts.append((x, y))
    return pts


def _head(p_from, p_tip, color):
    (x1, y1), (x2, y2) = p_from, p_tip
    dx, dy = x2 - x1, y2 - y1
    length = math.hypot(dx, dy) or 1.0
    ux, uy = dx / length, dy / length
    px, py = -uy, ux
    bx, by = x2 - ux * 9, y2 - uy * 9
    pts = f"{x2:.1f},{y2:.1f} {bx + px * 4.5:.1f},{by + py * 4.5:.1f} {bx - px * 4.5:.1f},{by - py * 4.5:.1f}"
    return f'<polygon points="{pts}" fill="{color}"/>'


def arrow(d, color, sw=2, dash=None, bidir=False):
    pts = _pts(d)
    poly = "M" + " L".join(f"{x},{y}" for x, y in pts)
    dd = f' stroke-dasharray="{dash}"' if dash else ""
    out = f'<path d="{poly}" fill="none" stroke="{color}" stroke-width="{sw}"{dd}/>'
    out += _head(pts[-2], pts[-1], color)
    if bidir:
        out += _head(pts[1], pts[0], color)
    return out


def esc(s):
    return s.replace("&", "&amp;").replace("<", "&lt;").replace(">", "&gt;")


def rect(x, y, w, h, rx=6, fill=BG, stroke=FG, sw=1, dash=None):
    d = f' stroke-dasharray="{dash}"' if dash else ""
    return f'<rect x="{x}" y="{y}" width="{w}" height="{h}" rx="{rx}" fill="{fill}" stroke="{stroke}" stroke-width="{sw}"{d}/>'


def text(x, y, s, size=12.5, weight=400, anchor="middle", fill=FG, family=FONT):
    return (f'<text x="{x}" y="{y}" font-family="{family}" font-size="{size}" font-weight="{weight}" '
            f'text-anchor="{anchor}" fill="{fill}">{esc(s)}</text>')


def route(d, color, marker, sw=2, dash=None):
    return arrow(d, color, sw=sw, dash=dash)



def box(x, y, w, h, title, sub_lines, mem=False, stroke=None, sw=None, dash=None):
    fill = SURF if mem else BG
    st = stroke or FG
    s_w = sw if sw is not None else (2 if mem else 1)
    out = [rect(x, y, w, h, fill=fill, stroke=st, sw=s_w, dash=dash)]
    cx = x + w / 2
    mid = y + h / 2
    out.append(text(cx, mid - 2 if len(sub_lines) else mid + 4, title, size=12.5, weight=600))
    for i, (sline, fam) in enumerate(sub_lines):
        base = mid + 14 + i * 14
        out.append(text(cx, base, sline, size=10.5, fill=GRAY, family=fam or FONT))
    return out
